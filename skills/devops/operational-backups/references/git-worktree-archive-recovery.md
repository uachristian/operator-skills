# Git worktree archive and recovery gates

- Distinguish a checkout from a standalone repository before whole-folder offload. A worktree's `.git` file may point into the active installation's shared common directory. Preserve the root's hidden/ignored/untracked files plus a verified selected-ref Git bundle and its worktree-specific admin metadata (HEAD/index/ORIG_HEAD/reflog). Never copy/delete the entire shared live Git directory merely to archive one worktree.
- Enumerate detached worktree HEADs as well as named refs. A clean detached worktree can retain commits absent from both the installed tip and every named branch; deleting its admin state before creating independently verified history recovery can strand those commits. Do not treat an on-disk `.git` pointer or another unrelated archive as proof of history coverage. Preserve exact dirty/untracked/ignored evidence separately from Git objects.
- Bind selected refs to exact commits before packaging and verify an independent clone/import. Preserve historical evidence refs as well as the current checked-out branch when they differ. A bundle excludes untracked qualification evidence and dirty source overlays; archive those separately as part of the root.
- Restore historical bare bundles using the explicit manifest branch/commit/tree. A bare mirror can have complete data while HEAD points to nonexistent `main`; generic HEAD/checkout assumptions can falsely declare recovery broken.
- Exercise dirty overlays against the exact recorded original commit inside disposable isolated storage and verify every recorded dirty-file hash. Do not infer complete recovery from `git bundle verify` alone, which is not the same as an independent clone and correct dirty-state restoration.
- Preserve external interpreter symlinks instead of following them into the production runtime. Archived venvs with absolute shebangs/external Python links are not independently portable; document compatible interpreter/rebuild requirements and never execute a known contaminated historical test environment as proof.
- Sanitize inherited GIT_* variables and disable system/global Git configuration and hooks for isolated recovery commands. Keep all clone/checkout/apply writes in a path-verified disposable repository, never an ancestor-discovered live repository.
- When FileVault is off and recovery material may be sensitive, stage restored content inside an independently encrypted APFS image with owner-only independent key custody. Prove key-based reopen before use. Keep image/key until writers exit and required encrypted archive/recovery proof is retained; never detach an in-use image.
- Run potentially long encrypted-volume clone/checkout/verification jobs as tracked background commands with completion notification. An outer tool transport may time out before a requested foreground limit. Reconcile actual processes, current step, receipts and partial indexes before resuming; do not restart the entire capture.
- A timed-out `git bundle create` parent can leave its pack writer still writing the task-specific `.bundle.lock`. Prove writer ownership from its exact open output descriptor/process group. Do not remove that file or start duplicate packaging. After the writer exits, an unheld completed candidate may be checked for exact refs/header and independently cloned before it is promoted; a partial or failed candidate remains untrusted.
- Retire an approved registered worktree with the supported exact worktree operation after archive/cloud/source-identity gates, retaining shared refs/history. Do not broadly prune worktrees or remove roots that still anchor live processes. A separate ordinary source/evidence folder may use exact descriptor-safe removal only after the same recovery checks.
