# Advanced quality pitfalls

Load for the affected failure domain. Do not apply every domain-specific example to every build. Preserve required security and acceptance evidence.

## Common Pitfalls

- Writing an implementation plan with tasks too large to verify.
- Keeping spike code that was meant to be disposable.
- Applying a plausible fix before reproducing the bug.
- Adding tests after implementation and calling it TDD.
- Letting a debugger session hang without PTY/background tracking.
- Reporting tests passed without showing real command output.
- Exporting synthetic `HOME`, `HERMES_HOME`, profile roots, credentials paths, or similar test variables in a persistent terminal session and then running a live readback from the same shell. Hermes terminal environment persists across calls. A stale `TMPDIR` is especially deceptive after a disposable reviewer directory is deleted: compilers and package managers can fail before reaching the intended RED test. Prefer `env VAR=value command`, explicitly pin `TMPDIR=/tmp` for exact-candidate gates, or use a subshell (`( export VAR=...; command )`) for probes. Before any production-state read/write, explicitly pin the intended profile root and print/assert the resolved canonical state paths in a fresh process; otherwise a healthy test-root scan can be mistaken for production verification.
- Designing or implementing from a conversational schema proposal without first reading the live validator constants, canonical fixtures, normalized field names, database DDL, `CHECK` constraints, and persistence shape. Before the first production record, validate the real payload—not just a fixture—and inspect `PRAGMA table_info(...)` or equivalent before writing readback SQL; JSON fields are not necessarily promoted to table columns.
- Chaining a test command with later commands using `;` and then trusting the shell's final exit code. A failing test can be masked by a succeeding cleanup or diff check. Use `set -e`, `&&`, or capture and assert each return code explicitly. The same applies to pipelines: `psql ... | tee log` normally returns `tee`'s status, so use `set -o pipefail` plus the tool's own fail-fast option (for PostgreSQL, `ON_ERROR_STOP`) before treating a logged verification as green.
- Enabling `set -u` in a Hermes terminal persistent-shell command without accounting for the host teardown wrapper. On macOS Bash, the post-command state snapshot may reference an unset `BASHPID`, turning an otherwise successful operation into a final `unbound variable` exit. Prefer `set -e` plus explicit pipeline/error checks for ordinary Hermes terminal calls, or contain `set -u` in a subshell and disable nounset before returning to the wrapper. Always verify destructive side effects by direct readback when this teardown error appears.
- Treating access-token issuance time (`iat`) as proof of recent interactive authentication. Silent refresh can renew `iat` without password/OTP/TOTP/WebAuthn interaction. Require fresh signed AMR evidence, a server-held user+session grant with bounded event-relative expiry, one-time atomic consumption, and rejection of re-minting from the same consumed AMR event. When rollback-proving PostgreSQL function ACLs, compare effective/normalized privileges rather than raw `proacl` array order.
- Using `has_function_privilege(...)` to prove a **direct** PostgreSQL role grant. It reports effective authority through `PUBLIC` and role inheritance, so a service grant can be missing while the check remains green until `PUBLIC` is revoked. Inspect normalized `aclexplode(proacl)` rows for direct grants, bind reviewed authority to exact `regprocedure` signatures, and reject both missing and unexpected signatures. Aggregate counts and `proname LIKE 'app_auth_%'` regrant loops are diagnostics—not fail-closed allowlists—because an identity swap can preserve counts and silently authorize a new owner-context function.
- Treating delegated summaries, commits, paths, or side effects as shared-state proof. Subagents may operate in isolated workspaces; verify every claimed artifact from the main session by reading the path, commit, or remote before depending on it.
- Reconstructing an unseen checksum suffix from a truncated tool display. A visible hash prefix is not artifact identity: rerun the exact hash command, capture the full digest from untruncated output, and pass only that verified value to reviewers/manifests. If the report or archive changes afterward, re-hash the changed artifact and patch every dependent reference before release.
- Using broad regex across serialized audit rows to infer side effects. A pattern such as `write_performed.*true` can cross into an unrelated later field such as `read_only:true`. Parse JSON/JSONL and test the exact key/value, then report only sanitized action/source/outcome metadata.
- Treating a failed quality assertion as proof the implementation is wrong without first inspecting the rendered output. When an assertion fails, read the actual output, decide whether the behavior or the assertion is incorrect, then tighten the guard to match the real acceptance criterion.
- Treating static browser-source assertions or `node --check` as proof a supported render branch works. Syntax checks do not resolve branch-local names, and substring assertions only prove bytes exist. Execute the risky state with a minimal DOM harness and require no exception, then keep source assertions only as secondary contract guards.
- Treating OpenAPI/YAML source substrings as the machine contract. In flow mappings, unquoted commas split prose into additional keys, so a visually complete response description can parse as a truncated `description` plus invalid null-valued fields while text tests stay green. Parse exact parent and target bytes with a real YAML parser, inspect Response Object keys, and assert the parsed semantic phrase.
- Treating a live UAT failure as source-code evidence when the harness launches a prebuilt image/tag. Inspect the harness before debugging product logic; compare its build-contract hash/image ID with the current source, then run the canonical hash-aware rebuild/up target and repeat UAT. Do not replace this with an ad hoc untracked image build—the final evidence must bind reviewed source, image identity, and runtime behavior.
- Hardening a synthetic-only prose gate by extending a finite punctuation, registration-layout, or VIN-threshold allowlist. Common separators, Unicode digits, IDN email text, vanity phones, identifier spacing, and cross-field fragments will keep creating bypasses. Inventory the exact persisted field set and preserve field-local markers first. If the milestone does not need numeric prose, freeze the enforceable grammar after the first adversarial cycle: reject non-ASCII decimal digits before NFKC normalization, normalize IDNA dot variants, remove each complete reserved email/phone independently, then reject every residual decimal digit across the aggregate. Require other synthetic numbers in words. Do **not** remove blanket `SYNTH-<digits>` tokens before residual checks: one token or several tokens across fields can launder a phone, registration, or VIN. Bound reserved-phone syntax so an optional country code is explicit (for example `+1`) and conventional separators cannot absorb an unrelated leading digit. Pair rejection cases with healthy controls for quoted/bracketed reserved emails, Unicode-dot suffix attacks, multiple reserved contacts, explicit `+1` reserved phones, ordinary prose, and the canonical HTTP/UAT producer. Update README/OpenAPI/UI fixtures in the same batch and stop broad reviewer recursion once the frozen matrix passes. If numeric prose is genuinely required, use structured field-specific values or a reviewed candidate parser and narrow the no-real-data claim.
- Treating source/restored equality or a global RLS count as a canonical restore security contract. A same-bad baseline and count-preserving decoy swap can pass both. Hash one sorted ACL/owner/policy/RLS/FORCE row per promoted write table, use that same exact table set in UAT accepted-baseline hashing, and require disable/restore mutation probes to diverge and reconverge.
- Treating exact function-name/signature/trigger counts as proof that security-critical PostgreSQL code is canonical. `CREATE OR REPLACE FUNCTION` can preserve signature, owner, ACL, trigger binding, and migration-ledger checksum while replacing the guard body with `RETURN NEW`; source/restored parity then faithfully preserves the same-bad definition. Bind each expected `regprocedure` to a canonical normalized `pg_get_functiondef` or reviewed body hash plus owner, language, security flags, `proconfig`, ACL, and exact trigger binding. Mutation-probe a same-signature no-op replacement and require both live and restore verification to fail.
- During full-suite remediation, editing many tests before re-running a targeted subset. Bucket failures first (product regression vs stale assertion vs host-specific assumption), fix in small batches, rerun the targeted subset, then rerun the full suite before claiming the system is healthy.
- Running multiple Next.js build/start gates concurrently in the same checkout. `next build` replaces the shared `.next` directory while a long-lived accessibility or browser server may still be reading it, producing mixed-mode or viewport-boundary failures unrelated to either immutable candidate. Serialize build-backed gates, or give each gate a detached worktree/output directory; bind every background-process verdict to its start time, exact commit, and isolated build artifact before using delayed completion notifications as release evidence.
- Treating fixed wall-clock sleeps as async/thread synchronization. Under parallel load, event loops and heartbeat threads may not receive the expected CPU slice. Prefer bounded condition polling, controlled timer callbacks, or event handshakes; reproduce the failure alone several times, and if failures shift while suite runtime inflates, rerun the final canonical gate at a documented bounded worker count rather than repeatedly saturating the host.
- Treating a passing full suite as final after later changing dependencies or the active venv. If post-suite health gates such as `pip check`, lock checks, or security audits require dependency repair, verify the specific gate and run the full suite again against the repaired environment.
- Running audit tests in a canonical checkout. Test runners can create `__pycache__`, coverage, or framework cache artifacts even when bytecode/cache flags appear disabled. Prefer a disposable clone or temporary worktree; otherwise record status first, remove only artifacts created by the audit, and verify tracked status afterward.
- Attributing tests to a frozen commit without rechecking `HEAD` immediately before and after the command. A clean worktree does not mean the branch tip stayed fixed: another agent can commit concurrently, so tests may execute remediated or otherwise different source while all static reads used `git show <target>`. Capture `HEAD` on both sides; if either differs from the target, invalidate the run as exact-commit evidence unless every loaded source/test object ID is proven identical. Prefer an isolated detached worktree for runnable exact-commit gates.
- Letting disposable PostgreSQL tests inherit arbitrary pytest temp paths or captured pipes. Unix-socket paths have a small platform limit, so create the test cluster under a short `/tmp/<prefix>` root rather than a deeply nested pytest directory. When `subprocess` captures `pg_ctl` output, start with `pg_ctl -l <logfile>` so the long-lived server does not inherit and hold the capture pipe open. Track whether startup succeeded, stop in `finally`, and delete only that generated root.
- Building a sparse integration overlay by copying only today's diff onto an older target `HEAD`. Prior canonical overlay modules or migrations may be absent from that target commit, creating false missing-import or migration-history failures. Materialize the full declared overlay subtree in a detached target worktree, run overlay tests plus the target build there, and keep the dirty canonical target checkout untouched.
- Promoting static-analysis output directly to a defect list. Reproduce reachable behavior and inspect dynamic imports, generated placeholder SQL, non-security hashes, URL validation, and subprocess argument construction before assigning severity.
- Treating a new fail-closed validator as proven after only adversarial rejection tests. Pair every negative RED/GREEN invariant with a positive control built by the canonical producer, then—when authorized—load the current sanitized real artifact through the installed runtime and assert its semantic counts. A guard that blocks the exploit but rejects all healthy artifacts is a production regression, not a safe remediation.
- Treating a green remediation suite as proof every acceptance criterion is closed. Convert each filter, sanitizer, dedupe rule, and public-action revalidation guard into an adversarial truth table. In particular, probe blocked records plus neutral metadata, shorter synonyms not present in the regex, ambiguous legitimate phrases, duplicate display IDs backed by different internal IDs, and source text that was appended or shortened. Symmetric prefix checks are not valid change detection.
- Reporting a parameterized pytest expansion as the number of logical HIGH paths, or treating absent pagination metadata the same as present-but-incomplete metadata. Name each logical path once, report expanded cases separately, and use endpoint-specific completeness proofs: a verified non-paginated child endpoint may accept only explicit `success: true` plus list-shaped `data` and no error envelope when `meta` is absent; any present `meta` must itself be complete and terminal, and present-null/partial metadata must fail. Pair that rejection matrix with a producer-built positive fanout control using the exact healthy envelope so the validator is proven selective rather than fail-shut.
- Assuming the exact CI command is reproducible merely because it passes in the developer's active environment. Installed framework modules, live profile paths, credentials, environment variables, and import-time constants can hide undeclared dependencies. For private-repo remediation, run the workflow in a clean clone/container or throwaway minimal virtualenv with only declared CI dependencies; override runtime homes before module import and use narrow test doubles for host-framework APIs.
- Treating a pushed branch as verified when the remote ref exists. Poll the **latest run for that exact branch tip**, then assert remote SHA = local HEAD = workflow `headSha`, status is completed, conclusion is success, and the local worktree is clean for every repository.
- Assuming a GitHub checkout uses the same directory basename as a hand-maintained local clone. Path safety guards should validate repository markers or accept the canonical remote checkout name; never hardcode a local `-repo` suffix as the sole identity check.
- Assuming a delegated review is read-only merely because its prompt says so. When subagents can reach shared absolute paths, prefer isolation over instruction: use an immutable `git archive` snapshot for content-only review, or a disposable detached worktree at the exact commit when the reviewer needs Git metadata/tests. Reviewer teardown may delete tests or temporary artifacts even after reporting “no files modified.” Verify the real implementation worktree afterward and restore unexpected tracked deletions only from the verified commit; otherwise record hashes before delegation, compare them afterward, and restore drift from a verified backup.
- Running Git-dependent gates inside a plain `git archive`. Archives intentionally omit `.git`, so scanners that call `git ls-files`, tests that call `git show`, and history-based invariants will fail even when the source is sound. Use a disposable detached worktree for exact-tip gates that need Git metadata; reserve archives for content-only review. If CI uses a shallow checkout, encode frozen-file invariants as reviewed SHA-256 constants or explicitly fetch the required history—do not assume an old commit object exists.
- Using one convenience-excluded recursive file walk as both a secret scan and a synthetic-data authorization gate. Treat these as two surfaces: enumerate tracked plus nonignored files with Git (and every file when Git metadata is absent), then separately inspect ignored local paths that must never hold credentials or real data. Tracked files under build/cache names still require scanning; NUL/binary classification must not suppress token checks; ignored `.env`, key/database, import/export, upload, and real-data fixture paths must fail during a blocked foundation phase.
- Trusting a lower-than-expected test count after shared-state or delegated work. Treat collection-count drift as evidence that tests may have disappeared. Compare tracked status and expected test paths before and after the suite, then run the release gate from the immutable commit in an isolated Git worktree rather than accepting a green but incomplete collection.
- Treating every failed post-delete read as proof that the object is absent, or assuming a generic helper field such as `public_delete_attempted` will satisfy an orchestrator that requires `public_action_taken`. Probe definitive not-found separately from timeout/auth/rate-limit/5xx, and carry one canonical terminal vocabulary through helper JSON, wrapper envelopes, normalization, classification, and durable completion. Verify both ambiguous and genuinely successful rollback paths.
- Letting repair review recurse without a completion budget. Define the approved scope, required gates, and cutoff before delegation. If an agent stalls or repeatedly reviews its own diff, stop it, preserve the worktree, take over the existing edits, run the complete suite, and close once the approved gates pass. User frustration about elapsed time is a first-class signal to eliminate optional reviewers and finish the shortest safe critical path.
- Treating the absence of a recognized OAuth Connect Link as proof that an account is already connected. A null, malformed, arbitrary JSON, nested failure, or general-app link may arrive without `isError: true`. Parse bounded JSON failure envelopes before link extraction, recognize singular/plural failure forms from the reviewed provider vocabulary, reject every unrecognized link regardless of the error flag, and require positive capability-specific evidence at the exact parent/child path for `ALREADY_CONNECTED`—never a recursive leaf-name match. Preserve a canonical healthy-payload control plus negative cases for misplaced evidence, nested/escaped links, and valid evidence combined with a failure object.
- Creating new files, migrations, seeds, scripts, or containers in a fail-closed repository while postponing exact artifact/migration/restore allowlist registration. Register each artifact in the canonical validator and ordering contracts in the same edit batch, then run the static gate immediately. Otherwise a correct feature can consume the release budget while the known canonical gate remains red.
- Treating an immutable-review verdict as still valid after editing the working tree. The moment remediation begins after reviewers were dispatched, mark their target superseded, preserve their findings as input only, and require a fresh exact-tip commit plus final gates/review before RELEASE or deployment. Reserve completion budget before the first freeze: implementation, one adversarial review, one remediation pass, final exact-tip verification, deployment, and readback. When the remaining budget cannot close those gates, stop with deployment held and report the exact committed/uncommitted boundary rather than spending the final calls on optional cleanup.
- Running an installer from a moving checkout after a narrower commit was reviewed. Later commits can silently add allowlisted files or change installer inputs even when the reviewed subsystem is untouched. Materialize a detached worktree at the reviewed commit, rerun its focused suite, secret scan, and installer dry-run there, then deploy from that exact worktree and compare the live readback against its manifest.
- Sending broad repository-wide or multi-question audits to background reviewers under one wall-clock timeout. Give a reviewer one immutable diff or commit, one subsystem, one explicit question, and bounded verification commands. A timeout produces no review evidence, but it may leave valuable uncommitted work. Before cleanup, inspect the isolated worker directly, preserve tracked plus untracked content as a binary-safe patch (use intent-to-add for untracked files), hash it, and keep the worker worktree intact. Review and test the patch as untrusted partial work before applying it to the controller lane. Do not re-dispatch the unchanged task; reserve a fresh independent reviewer for the final integrated exact tip.
- Weakening a canonical repository-path guard because an operational script refuses a feature worktree. Look for a supported exact-root override and scope it to one process; otherwise use an authorized disposable clone. Never widen the production guard merely to make candidate verification convenient.
- Treating one database backup as both rollback and Phase N restore evidence. Keep the pre-migration backup as the rollback point, then take a second post-migration backup after direct ledger/schema readback for the Phase N restore drill. A Phase N-1 backup should fail the Phase N contract. Whenever a correction creates a newer recovery backup, enumerate every backup-stamp occurrence across ADRs, evidence summaries, rollback instructions, runbooks, and machine state; assigning the newest stamp correctly in one section does not compensate for an operational rollback line that still points to an intermediate backup. If that stale recovery path would omit a security/integrity correction, treat the documentation contradiction as high severity and HOLD.
- Treating one verifier's `temporaryDatabasesRemoved=true` as proof that the whole release environment is clone-clean. Per-run exact-name cleanup and family-wide hygiene are separate gates. After all UAT, migration, and restore checks, enumerate every current and legacy/debug database **and** container prefix; require the declared allowlist (normally zero), inspect exposure and creation times for leftovers, and reconcile the live census with prose such as “destroys every clone.” A stale clone predating the final commit still makes a global handoff claim false.
- Accepting a zero-result security query without proving its subject set. A misspelled function/table allowlist can yield zero forbidden grants and falsely pass. First assert the exact expected function signatures, tables, triggers, or policies exist; then assert the forbidden count is zero. Static tests for bounded dynamic-SQL loops should validate the exact allowlist and template, while live catalog probes validate the expanded identities.
- Treating `SELECT count(*) FROM scalar_function()` as the scalar function result in PostgreSQL. A scalar function used in `FROM` produces one row, so `count(*)` returns `1` regardless of whether the function returned zero or many violations. Read the value directly (`SELECT scalar_function()`), add a regression that forbids the count-wrapper pattern across every UAT/live/restore verifier, and regenerate evidence at the corrected exact tip.
- Letting a lock helper own the only advisory-lock descriptor while the protected parent continues the critical section. Helper death releases that lock before the parent can react, so even fail-stop event handling leaves an overlap race. Open and validate the lock file in the parent, pass that descriptor to a one-shot `flock` helper, retain the inherited locked descriptor through the callback, and close it in `finally`; prove the helper is already gone while a second entrant remains blocked.
- Parallelizing browser screenshot/console/navigation calls against one shared browser session. These calls are not independent: the active page can change or reset to `about:blank`, and a blank screenshot does not by itself prove a renderer defect. Serialize browser operations; verify `location.href`/`document.title` before DOM assertions after screenshots, and re-navigate to the exact artifact if the binding was lost. Do not count errors from an unrelated/blank page as candidate application failures.
- Treating Playwright `requestfailed` as coverage for HTTP 4xx/5xx, or checking lazy images only before client interactions. Completed error responses need a `response.status() >= 400` listener, and any interaction that mounts/changes media needs the same `complete`/`naturalWidth` sweep after the state change.
- Treating `SELECT ... FOR SHARE` as a read-only operation compatible with SELECT-only ACLs. PostgreSQL locking reads (`FOR SHARE` and `FOR UPDATE`) require UPDATE authority; a plain dashboard SELECT can pass while the mutation path returns a sanitized 500. Reproduce the exact query as the application role, remove redundant locks on runtime-immutable catalogs/templates when an aggregate lock already serializes the transaction, and do not widen ACLs merely to satisfy an unnecessary lock.
- Designing an append-only evidence table with a blanket `BEFORE UPDATE` rejection trigger when the runtime must finalize `pending` rows. Preserve immutable identity, but implement one narrowly constrained `pending → final` transition that proves exact changed columns, optimistic version, parent state, recorder/link shape, and completed-parent immutability. For completion coverage, make child mutations and parent completion contend on the same parent `FOR UPDATE` lock; PostgreSQL does not permit row-lock clauses on aggregate queries.
- Revoking direct application-role DML but granting a `SECURITY DEFINER` replacement that trusts the HTTP parser. The function is now an application-role security boundary and must independently revalidate tenant, parent tuple, assignment kind, target-principal eligibility, input bounds, current state, deterministic lock order, and affected-row cardinality. Probe direct role calls for the exact ineligible-principal and open-state constraints, then prove the healthy path.
- Running a historical upgrade assertion as the forced-RLS table/schema owner and assuming it can see every tenant. `FORCE ROW LEVEL SECURITY` applies to the owner, and `SECURITY DEFINER` does not help when that definer is the same forced-RLS owner; without tenant context, the assertion can vacuously see zero rows and ledger successfully. Use an explicit transaction-local bootstrap/BYPASSRLS scan or verified complete tenant enumeration, and apply the actual migration to a malformed non-default-tenant fixture so role switching, RLS visibility, exact error identity, and no-ledger-on-failure are all proven. The fixture must satisfy every unrelated parent/tenant/FK invariant and violate only the historical rule under review; if `session_replication_role=replica` or disabled triggers are used to construct it, explicitly re-prove those relationships before accepting the rejection. Do not leave a superuser-owned callable function behind.
- Guessing package scripts or build targets during a bounded release. Inspect the repository's declared `package.json` scripts, Makefile, or task runner first, then run the canonical command. Reserve the remaining call/tool budget for the full suite, disposable database UAT, restore, scans, exact-tip review, release, and readback before spending it on optional UI polish.
- Keeping remediated audit findings in present tense beneath a single top-level “closed” note. Mark each finding historical/remediated, write original defects in past tense, replace required fixes with implemented resolutions, and keep the active priority list limited to unresolved work.
